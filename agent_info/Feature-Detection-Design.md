# Untargeted Feature Detection — Design Plan

Design for extending the Rust FlashLFQ port to detect **all likely peptide features in the
MS1 data**, not only those with an associated PSM. Captures the design discussion and the
decisions taken on 2026-07-04.

## Goal (decided)

**Fully de novo feature inventory.** Produce an unbiased MS1 feature map: detect and quantify
*every* isotope-pattern feature (neutral mass + charge + RT-resolved intensity) regardless of
whether any run ever identified it. PSM/MBR identities are attached only as **annotation** on
top of the feature map, not as the source of the seeds.

This is a superset of, and orthogonal to, the current pipeline:

- **Current (targeted):** start from an `Identification` (mass + RT + charge from a PSM) →
  `get_xic` → `get_isotopic_envelopes` (given the theoretical distribution) → `cut_peak` →
  charge aggregation → FDR. MBR loosens this to "borrow a donor run's ID" but still needs
  *someone's* PSM.
- **New (untargeted):** generate the seeds **from the raw MS1 data**, infer charge and
  monoisotopic mass with no ID, then quantify and (optionally) annotate.

## Validation strategy (decided)

**Port one real mzLib deconvolution algorithm to preserve the parity-gate discipline.**
Chosen algorithm: **`ClassicDeconvolutionAlgorithm`** (mzLib
`MassSpectrometry/Deconvolution/Algorithms/ClassicDeconvolutionAlgorithm.cs`). **IsoTracker is
explicitly out of scope.**

Porting a real mzLib algorithm keeps the project's core discipline intact: every layer diffs
against a C# golden generated by the real code (the L0–L6 / MBR pattern). The deconvolution
layer gets its own golden — a C# generator that runs `ClassicDeconvolutionAlgorithm` over the
K562 test mzMLs and dumps `(neutral mass, charge, mono m/z, intensity, score)` per scan, which
the Rust port diffs at the standard tolerance (ints/counts exact, floats rel-1e-6).

Note the honest boundary: cell-parity guarantees the *deconvolution* matches mzLib. It does
**not** prove the *assembled feature map* matches any external tool (Dinosaur/OpenMS/MaxQuant),
because mzLib has no full untargeted-feature-detection engine to diff against. Feature assembly
(charge merge + RT peak grouping into one feature record) is validated by synthetic ground
truth and internal consistency checks, not by an external golden.

## What already exists and is reusable

The port already contains most of the primitives. Big head start.

| Primitive | Location | Role in feature detection |
|-----------|----------|---------------------------|
| Untargeted XIC extraction | `peak_indexing.rs::get_all_xics` | Greedy, intensity-descending, claim-as-you-go seed generator — every m/z trace in the run without any ID. This is the mzLib IsoTracker XIC path but the routine itself is ID-agnostic and reusable. |
| Binned m/z index | `peak_indexing.rs::PeakIndexingEngine` | Fast m/z lookups for isotope-ladder walking. |
| RT peak splitting | `chromatographic_peak.rs::cut_peak` | ID-agnostic once fed a time instead of an MS2 RT. |
| Averagine model | `theoretical_isotope_distribution.rs::averagine_mass`, `expected_isotope_peaks` | The expected isotope envelope when you have **no** formula. |
| Correlation gate | `isotopic_envelope.rs::pearson` + correlation check | Observed-vs-expected envelope scoring. |
| Charge merge | `results.rs` `ResolveIdentifications` / `MergeFeatureWith` | Structurally the same as feature assembly, but re-keyed on **neutral mass** instead of **modified sequence**. |

## The one genuinely missing piece: ID-free deconvolution

`get_isotopic_envelopes` today is **given** the peakfinding mass, the theoretical distribution
(from the known modseq), and the charge. Untargeted detection has none of those — from an XIC
at some observed m/z it must **infer**:

1. **Charge** — test z = 1..N hypotheses.
2. **Monoisotopic mass** — from m/z + inferred charge, walk the isotope ladder to the mono peak.
3. **Reality/score** — build an **averagine** distribution at the candidate mass (not a
   sequence-specific one) and correlate observed vs. expected envelope.

This is exactly what `ClassicDeconvolutionAlgorithm` does. Porting it supplies the missing
inference layer; the rest is wiring existing primitives.

## Proposed pipeline

1. **Seed generation** — `get_all_xics` over each file's MS1 index → candidate traces
   (intensity-descending, deduplicated by claimed peaks).
2. **Deconvolution** (new, ported `ClassicDeconvolutionAlgorithm`) — per candidate, search
   charge + mono-mass hypotheses against an averagine envelope; emit scored
   `(neutralMass, charge, monoMz, intensity)` deconvolution results. **← parity-gated layer.**
3. **Feature assembly** — merge co-eluting charge states of the same neutral mass into one
   feature (re-key `ResolveIdentifications`/`MergeFeatureWith` logic on neutral mass); apply
   `cut_peak` for RT boundaries. Emit `DetectedFeature { neutral_mass, charge_states,
   apex_rt, rt_start, rt_end, intensity, score }`.
4. **Annotation** (optional, keeps this de novo) — link features back to PSMs/MBR by
   mass + RT tolerance so output can flag identified vs. unidentified features. Identity is a
   label on a feature, never a prerequisite for detecting it.
5. **Output** — extend the Parquet writer with a feature-map table
   (`feature_id, neutral_mass, charge, apex_rt, rt_start, rt_end, intensity, score,
   annotated_sequence?`).

## Open design questions to resolve during implementation

- **Charge range / z hypotheses** — mirror `ClassicDeconvolutionAlgorithm`'s configured range
  rather than inventing one, to stay parity-faithful.
- **Feature-assembly scoring** — no C# golden exists for the *assembled* feature; define a
  synthetic ground-truth fixture (known spiked masses/charges/RTs) to gate it.
- **Deduplication vs. the targeted path** — decide whether de novo features that coincide with
  an existing PSM-quant peak are merged or reported separately.
- **Performance** — `get_all_xics` over a full run is heavier than targeted tracing; may want
  an intensity floor / min-peak-count threshold (both already parameters on `get_all_xics`).

## Suggested task ordering (for a PLAN.md phase)

1. Port `ClassicDeconvolutionAlgorithm` into a new `src/deconvolution.rs` (averagine charge +
   mono-mass search over an envelope), unit-tested against synthetic envelopes.
2. C# golden generator: run mzLib `ClassicDeconvolutionAlgorithm` over the K562 mzMLs → per-scan
   deconvolution golden TSV. Rust parity gate diffs at rel-1e-6.
3. Wire `get_all_xics` → deconvolution → feature assembly into a new
   `engine::detect_features(file)` entry point.
4. Feature-map Parquet output + Python binding (`flashlfq_py.detect_features(...)`).
5. Optional annotation pass linking features to PSMs/MBR.

## Refined design — decisions taken in design session 2 (2026-07-04)

`ClassicDeconvolutionAlgorithm` is now ported (`rust/flashlfq-core/src/deconvolution.rs`,
`DeconEnvelope` + `classic_deconvolute` + a `LazyLock` 1500-entry averagine model; the
FlashLFQ `IsotopicEnvelope` name is deliberately **not** reused — the deconvolution envelope
is `DeconEnvelope`). Default `ClassicDeconvolutionParameters` are bottom-up: charge **1–6**,
4 ppm, intensity ratio 3, positive. On top of that port, the untargeted design is:

### Scope / objective
- **Bottom-up only for now** (charge 1–6). Top-down / high charge is out of scope.
- **Coverage objective:** explain as much MS1 signal as feasible; **initial target 50%.**
  Denominator = Σ of all MS1 centroid peak intensities across the run (≈ summed TIC).
  "Explained" = intensity claimed by an accepted feature. The coverage metric and the
  loop's stopping criterion are the same number.

### Pipeline (detect-then-refine)
1. **Seed ordering.** Work down high-TIC RT regions (per-scan summed intensity = the RT
   marginal), taking the tallest remaining m/z peaks as seeds. Greedy, claim-as-you-go
   (reuses `get_all_xics`' claiming). The busiest RT windows hold the most intensity, so
   this maximizes explained-signal-per-feature — at the cost of being the most chimeric
   region (expect the detector's multi-feature separation to be stressed there).
2. **Trace kernel (detection).** For z = 1..6, a sparse 2D matched filter:
   an isotope comb in m/z × a Gaussian in RT.
   - **Gaussian now, EMG later.** Real LC peaks are tailed, but a Gaussian *template*
     detects a tailed peak fine (matched filters degrade gracefully); tailing only bites at
     integration bounds, which `cut_peak` owns separately. No data-vs-data correlation gate
     at detection time — the template *is* the shape test.
   - **Evaluate sparsely, do not rasterize.** For a candidate (m/z, z, scan), look up the
     expected comb positions via `PeakIndexingEngine` across the window's scans and weight
     by (envelope weight) × (Gaussian in RT). The RT axis comes from `get_xic`; the kernel
     is a scoring/grouping layer over existing XIC + index machinery, not a new convolution
     engine.
   - **Comb runs both directions:** seed ± n·(C13−C12)/z (use the exact
     `C13_MINUS_C12 = 1.0033548`). The seed is the *most intense* peak; for mass ≳1500 Da the
     monoisotopic peak is at *lower* m/z and heavy isotopes at *higher* m/z, so a
     one-directional comb would misassign the mass.
   - **Envelope weights — closed-form Poisson first, benchmark averagine later.**
     The peptide isotope envelope is Binomial(n_C, 0.0107) ≈ Poisson(λ), λ ≈ 0.00048·M
     (carbons-per-Da × ¹³C abundance) — one parameter, no table lookup. Start here.
     Alternative to benchmark against: reuse the already-precomputed averagine intensities as
     the comb weights (the table is free; only ClassicDecon's ratio-bounds + adjacent-charge
     logic is expensive). **Decision: implement both, compare trade-offs; Poisson is the
     starting default.**
   - **Cross-z non-max suppression is required.** A z=2 comb is a subset of z=4 and z=6
     (spacings 0.502 / 0.251 / 0.167 Th), so a real z=2 feature partially fires higher-z
     kernels. Score all six z, keep the best, suppress its harmonics.
3. **Window + averaging (refinement input).** Determine the RT window from the data: assume
   ~36 s chromatographic peaks → derive MS1-scans-per-36 s from the median MS1 scan spacing.
   Use ≈ **FWHM** (not full peak width) for the average, to avoid pulling co-eluting
   neighbors into the composite. Later: bootstrap — measure the actual FWHM of detected
   features and feed it back. Averaging the window's scans raises SNR ~√N and produces a
   composite spectrum for the final decon.
   - **Port mzLib's `SpectralAveraging` — default-config subset first.** Full project is
     bigger than ClassicDecon (m/z binning/alignment, several outlier-rejection algorithms,
     several weighting schemes). **Decision: port binning + the default rejection/weighting
     config faithfully (golden-gated), stub the alternate rejection algorithms until needed.**
     The m/z binning is load-bearing — it's what gives the composite its mass accuracy.
     **Done (`rust/flashlfq-core/src/spectral_averaging.rs`).** `average_spectra(x_arrays,
     y_arrays, params)` ports `SpectraAveraging.MzBinning` verbatim: TIC normalization
     (all four `NormalizationType` variants), `floor((mz − minX)/binSize)` binning with
     zero-padding of absent spectra, weighted-mean bin collapse. Default config = `NoRejection`
     + `WeightEvenly` + `RelativeToTics` + bin 0.01. `WeightEvenly`/`TicValue` weighting ported;
     `MrsNoiseEstimation` weighting and the six clipping rejections `unimplemented!()`-panic
     until a config needs them. File-level scan windowing (`SpectraFileAveraging`) is out of
     scope — feature detection supplies its own window. Per-bin: `mz = mean(real peak m/z)`,
     `intensity = Σ(normalized real intensities) / numSpectra`. Six unit tests
     (hand-computed); no C# golden generated yet.
4. **Final deconvolution.** Run the parity-gated `classic_deconvolute` on the **averaged
   composite** → precise monoisotopic mass + z + envelope. This keeps ClassicDecon's C#
   golden meaningful (per-spectrum) while the trace kernel does the RT-aware assembly
   ClassicDecon structurally can't.
5. **Feature assembly — charge-state consensus on candidate masses.** Group co-eluting
   charge states of the same neutral mass (RT apex/window agree AND neutral masses agree
   within tolerance — the design's "re-key on neutral mass" step). Then **intersect the
   candidate-mass sets across charges**: the true monoisotopic mass appears in every charge
   state's candidate set, while spurious ±1 Da predictions do not consistently recur across
   charges — so this **resolves the monoisotopic off-by-one problem**, not just averages down
   noise. Practical form: pool candidates from grouped charges, cluster within a mass
   tolerance, take the cluster with cross-charge support (soften strict "all charges" to
   "≥2 charges, weighted by support count" for robustness).
   - **Required port change — DONE.** `DeconEnvelope` now surfaces
     `monoisotopic_mass_predictions: Vec<f64>` (additive, parity-safe: `monoisotopic_mass` and
     all C#-matched fields unchanged; populated in `set_median_monoisotopic_mass` at the
     acceptance point). The consensus is done at **assembly** (`feature_refinement.rs`), not
     leaning on ClassicDecon's internal `ObserveAdjacentChargeStates` fold — more control,
     tested in isolation.
6. **Loop** to the 50% coverage target (or until the top remaining seed falls below an
   intensity floor).

### Validation (no golden exists for assembly — three gates, increasing realism)
1. **Synthetic spike-ins** (known mass/z/RT) → detection precision/recall.
2. **PSM recall on K562:** run untargeted detection, then measure what fraction of
   `AllPSMs.psmtsv` IDs are *independently* rediscovered by mass+RT+charge. Strong real-data
   gate, needs no golden.
3. **Coverage:** % MS1 intensity explained — the objective itself.

### Session 3 (2026-07-04) — first real-data run + hardening
First end-to-end run on a real file (`04-17-23_CA_Tryp_HCD_10min.raw`, 2689 MS1 scans, 17.6M
peaks) via `examples/detect_features_tsv.rs`. Changes made from what it exposed:
- **Coverage stop + seed floor.** `TraceKernelParameters` gained `coverage_target` (stop once
  that fraction of ΣTIC is explained — the design's primary stopping criterion; run used 0.75)
  and `min_seed_intensity` (noise floor; early-breaks the intensity-sorted seed loop). Together
  they bound runtime and focus on the big signal.
- **RT window is now a *time* window, not a scan count.** `rt_half_window_minutes` (≈2σ) replaces
  the scan-count `half_window_scans` (kept, legacy/unused): DDA interleaves variable MS2 counts
  between MS1 scans, so a fixed ±N-scan window spanned ~2 min and made over-wide features that
  over-claimed and split one elution into several. The matched filter now walks scans outward from
  the apex, gated by RT distance.
- **Intra-hypothesis peak dedup.** For high z the comb spacing `(C13−C12)/z` is small, so two
  isotope slots could resolve to the *same* physical peak — double-counting response/intensity and
  inflating the observed-isotope count. `score_hypothesis` now tracks a per-hypothesis `used` set.
  (Cross-feature claiming was already correct: one sequential `HashSet<PeakKey>`, accepted peaks
  inserted, scoring skips claimed peaks — no peak is ever assigned to two features.)
- **Consensus merges on RT-range *overlap*, not just apex proximity.** `features_link` now groups
  same-mass features whose RT ranges overlap (padded), collapsing residual duplicate features into
  one. Result: output duplication went 9% → **0%**.
- **Refinement windowing (perf).** `refine_feature` slices each window scan to the feature's local
  m/z neighbourhood before averaging (binary-searched), instead of binning the full scan — the fix
  for a multi-minute stall. Trade-off noted: `RelativeToTics` then uses the sliced TIC (negligible
  for the charge/mass inference).
- **Validation snapshot** (untargeted vs base-FlashLFQ PSM peaks; run is on the *uncalibrated* raw,
  reference reports *theoretical* masses): 75% of ΣTIC explained; ~2840 resolved features vs
  ~620 PSM peaks; recall 29% at (20 ppm, 0.3 min) rising to ~70% at (100 ppm, 1 min, ±2 Da) and
  ~84% loose — i.e. **good sensitivity, gated by mass accuracy**. A systematic **+10 ppm** measured
  vs theoretical bias is the raw's own (uncalibrated) mass error, not a detector fault; off-by-one
  monoisotope assignment is the next-biggest lever. `examples/detect_features_tsv.rs` writes
  resolved + `.detected`/`.refined` intermediate TSVs and reports recall against a reference.

### Session 4 (2026-07-04) — averagine comb weights, off-by-one, averaging-window cap
Higher-coverage runs + a PSM/untargeted join (`untargeted_vs_psm_join.tsv`) showed the
discrepancy breakdown vs the wide-tol PSM set: **exact 43%, mass-shift (off-by-one) 17%,
ppm-off 19%, rt-only 21%, unmatched 0.2%** — i.e. off-by-one is the biggest *fixable* bucket.
- **Averagine comb weights — implemented** (`CombWeightModel::Averagine`;
  `deconvolution::averagine_comb_weights`, keyed by most-intense mass, plus
  `averagine_intensities_from_mono`, keyed by the monoisotope). Benchmarked against Poisson at
  90% coverage: **240 vs 249** PSM peaks — *slightly worse*. Conclusion: the off-by-one is **not**
  in the detector's comb weights (the resolved mass comes from `classic_deconvolute`, not the
  comb). Poisson stays the default; averagine kept as a selectable option (`COMB_MODEL=averagine`).
- **Averagine off-by-one corrector — implemented + tested, NOT wired.**
  `feature_refinement::correct_monoisotope_offbyone` scores mono candidates (0, ±1, −2 ¹³C) by
  cosine similarity of the observed composite vs the averagine envelope. On real data it
  **regressed** recall (233 vs 249 — flips more correct monos than it fixes; the cosine metric
  isn't discriminative enough on chimeric composites), so it is left behind `#[allow(dead_code)]`
  with a note. Needs a strictly non-regressive gate before wiring.
- **Averaging-window cap — fixed (net win).** `refine_feature` was averaging the feature's *full*
  claimed-peak scan extent, which under the ±2σ detection window is ~100 MS1 scans in dense
  regions. Now capped to `MAX_SCANS_TO_AVERAGE = 7` scans centred on the apex (asserted), matching
  SpectralAveraging's small-window intent. Result at 90% coverage: **refine 124 s → 35 s**
  (3.5× faster), total 203 s → 126 s, and recall **40.2% → 41.0%** (tighter composite = cleaner
  deconvolution, less co-eluting interference).
- **Runtime profile** now logged per-step to chat + a `.log` file (appends across runs).
